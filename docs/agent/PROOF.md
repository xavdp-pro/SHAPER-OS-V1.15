# Proof of a Working Universe

> **Intent Classification**: GENERIC INTENT (Universal / Parameterized Blueprint)

The first DEV proof is a real loop: construction → order → action → audit → answer. Steps 0–3 require no browser. A graphical console or phone is an additional surface, not a prerequisite for agent execution.

| Step | Actual check | Required evidence |
| :--- | :--- | :--- |
| 0 | Fresh native tests, real stack boot and applicable live tests | Candidate revision, image digests, actual services and results |
| 1 | Ask what runs, list jobs, enqueue a dedicated test task | True answers and correlated job ID |
| 2 | Execute a task and recover its result | Terminal Queue state, persisted `job.result.answer`, correlated retained audit, independently inspected artifact/effect |
| 3 | Analyze a declared fixture file | Result agrees with its known contents, without invented values |
| 4 | Optional console and phone microphone | Same authorized order/effect/evidence path through text/voice |
| 5 | Blank TEST universe, fresh source/images, all applicable checks, then destruction | Recovery, Vault private storage and restart without rebootstrap, independently observed cleanup |

A transient SSE answer, health response or unjoined audit event cannot satisfy step 2. A byte-exact artifact check must compare actual bytes including trailing newlines, using an independent observer and explicit expected bytes; command-substitution trimming is not valid proof.

A fixture is real controlled input, not a fake downstream service. Dedicated real test mailboxes satisfy mail integration; unit doubles alone do not. Record incomplete checks as such. The [lifecycle](LIFECYCLE.md) adds clean recovery, production permissions, canary and acceptance before real production. Keep business apps separate from Helm.
