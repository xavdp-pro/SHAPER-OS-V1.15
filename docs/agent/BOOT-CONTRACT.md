# Development and Construction Boot Contract

> **Intent Classification**: GENERIC INTENT (Universal / Parameterized Blueprint)

## 1. Understand before acting

Enter through the [board](../CONTEXT-INDEX.md). Read the complete local [LAW](../../LAW.md), [RULES](../../RULES.md), this contract, the [operating contract](OPERATING-CONTRACT.md), and the finite foundation in the [governing map](../GOVERNING-CORPUS.md). Follow applicable specialist dependencies. Keep an external record of revision, exact read coverage, unknowns and conflicts; truncated output is not full reading. A summary is not a replacement.

## 2. Establish the mandate and work perimeter

For an existing project, verify the adopted corpus revision, project mandate,
declared scope, current architecture, applicable profiles, existing state and
evidence under [LAW's adoption contract](../../LAW.md#two-uses-and-explicit-adoption).
Use the existing project workspace and its versioned records. Apply the governing
contracts to the requested development or correction; do not restart universe
construction merely because this boot contract was read. Follow the construction,
deployment, engine-binding or migration steps below when the authorized work
actually requires them. The principal agent's full-reading obligations remain
unchanged.

For new construction, identify the intended result, human authority, role, jurisdiction, selected host, resources, dependencies, acceptance and recovery. A new realization may begin empty. Record this OS revision and create concrete intent, manifests, tests, code and recipes there. Local construction needs a capable authorized Podman/LXC host; remote work uses authorized SSH. Probe the real host before choosing its settings.

Authorized DEV uses the provider-equivalent full noninteractive execution mode without CLI sandbox or repeated approval prompts. The tandem directs construction and observes changing interactions. Resolve implementation details autonomously; a missing recipe is work, not a missing law. A missing human decision or credential blocks only its dependent action. Do not delete unknown state, use production mail for DEV/TEST, or promote beyond the mandate.

## 3. Materialize from intent

Generate parameterized host-specific construction, not a rigid monolithic installer. Install necessary dependencies within authority. Every declared unit has its intent, perimeter, source, dependency graph, private MariaDB, ports, storage and acceptance evidence. One functional unit is one Podman boundary; do not combine databases to simplify the first build.

Boot by the actual acyclic topology: establish required secret/data state, Logger, Queue, then the selected bridge and orchestration/Helm dependencies. The [reference procedure](../procedures/01-REFERENCE-UNIVERSE.md) owns the selected composition. Validate dependencies and optional capabilities explicitly; a service is not ready merely because its process exists.

## 4. Bind the engine and prepared context

Measure engines from the target host on the declared task shape and use the human's economic/privacy cursor. Apply the [cognition](../architecture/COGNITION.md), [bridge status](../contracts/bridge-status.md) and [common continuity](../intents/cognition-bridge.md) contracts. Create/load the session with prepared context, then resume its identifier with current context deltas, completed-action evidence and the precise task. Recover lost continuity before action.

## 5. Prove the integrated result

Run fresh native tests, real unit tests, real peers and the typed acceptance path. Demonstrate the downstream effect from the receiving system or independent observer, not only the sending agent's answer. Use dedicated real test mailboxes for mail integration. Simulated unit tests may isolate code but never prove live execution.

After integrated functional acceptance, finalize and enforce the designed roles, jurisdictions and action/type rights. Replay accepted integrated workflows under production permissions and complete the [lifecycle](LIFECYCLE.md) and [proof](PROOF.md) contracts before authorized promotion. TEST is rebuilt from scratch and then destroyed after evidence retention; production is not a scratch environment.

## 6. Correct the cause and preserve learning

A defect is fixed in its owning source and intent, with a regression test that fails before the fix. An instance-local patch alone teaches the next construction nothing. Report gaps against contracts rather than editing a law down to fit broken code. Bounded repair attempts lead to a resting `DEGRADED` state and escalation. Never mutate the active infrastructure that sustains the acting agent; use the parent.

For an external beta or independent review, preserve the supplied target and evidence, record reproducible findings, and apply authorized changes in a separate candidate/fork. Do not silently fix the reviewed target, claim the original passed, or publish an unrequested change. Diagnostic-only mandates remain read-only.

## 7. Credential and public-source discipline

Check secret availability through authorized references before the dependent operation. Do not track populated environment files, manufacture default credentials, paste secrets into reports, or propagate all credentials to every unit. The operator owns production domains and tunnel choices; reuse existing authorization and parameters. Verify the actual configuration, never assume it from a path or a previous run.

## 8. Deliver honestly

Keep atomic changes and actual contributor attribution, verify repository/remotes before an authorized publication, and report code written, checks performed, artifact deployed and human acceptance separately. State remaining gaps, exact reproduction/observation and next proof. Retain necessary evidence and remove only the task's disposable resources; do not leave a test universe running as production by accident.

The result is complete only when the requested function works under its contract with recorded evidence. A healthy endpoint, plausible assistant answer, stub bridge or a proposed next step does not substitute for that result.
