## Common cognition meaning

A human bounds the mission, role and jurisdiction. The human–agent tandem prepares
the relevant universe, mission, resources, relationships, rules, initial state and
expected evidence. A bridge provides a session in which this context is loaded;
later precise tasks resume that identified session and refresh the current
context, changes and record of previous actions and checks.

Durable action records belong to the responsible Runtime units. Reload them at
each session or resumption so completed work is recognized and uncertain effects
are reconciled before repetition. A session identifier or conversation transcript
does not establish perfect model memory, current authority or completed effects.
When continuity is lost, reconstruct the context and action state before acting.

The [generic bridge intent](../docs/intents/cognition-bridge.md) owns these shared
obligations. Provider session formats, CLIs, ports, authentication mechanisms and
model settings belong to scoped adapters. The selected reference uses
[OpenCode](../docs/intents/cognition-bridge-opencode.md); that composition choice
does not change the provider-neutral core. The
[Meta Muse profile](../docs/intents/cognition-bridge-meta-muse.md) is an optional
adapter profile, not the generic contract.

## Design security without obstructing construction

Plan the intended security while designing and implementing the application:
identities, ownership, trust boundaries, exchanges and future permissions inform
the structure from the start. In DEV, implement controls necessary to an
important functional requirement or to the agreed development perimeter; do not
require all production hardening to be coded before construction can progress.
Record what remains to be implemented.

The practical reason is that the human–AI tandem directs the authorized work and
follows the evolving application. Do not freeze fine-grained permissions too
early and repeatedly reprogram them by trial and error as interactions change.
Keep the intended boundaries visible during construction, then finalize and
enforce coherent production policies with the complete application view. Re-run
the accepted integrated workflows under those policies.

After the tandem accepts the assembled functionality and interactions, conduct a
dedicated hardening phase using the complete application view. Establish roles,
jurisdictions and action/type permissions, implement the required controls, and
verify their enforcement before production use. Functional acceptance starts
that phase; it does not substitute for it. The
[shared lifecycle](../docs/intents/cognition-bridge.md#security-by-design-followed-by-a-dedicated-hardening-phase)
explains how constructors apply this sequence.

## Production policies after construction

The human–AI tandem decides and implements production permissions appropriate
to each action or action type. Before dispatch, determine its role, jurisdiction,
resources, data access, allowed operations and applicable security conditions.
Enforce those rights in the actual Runtime and bridge execution, and verify the
result. Maestro schedules and Queue dispatches work within that policy; neither
grants broader rights. An existing policy authorizes matching work without
repeated per-call approval. Work outside it requires the corresponding policy
or mandate decision. Full DEV execution is not a blanket production policy.
