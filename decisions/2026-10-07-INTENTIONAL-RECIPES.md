# Intentional recipes and the ideal scene

Direction: **MANDATE**, 7 October 2026. This clarifies the nature of the
framework and the ownership of specialized recipes.

## The enduring asset is organized thought

SHAPER OS is an organized ideal scene expressed through intentions, laws,
responsibilities, relationships and logical construction recipes. It is not a
Debian package, an executable, an application or a code distribution. Its primary
reader is a capable AI agent; human explanations provide accessible gradients
into the same meaning.

The recipe gives the desired outcome, why it matters, boundaries, inputs,
outputs, state ownership, dependencies, construction order and recognizable
success. The agent interprets this material for the human's situation and
constructs the implementation in an orderly way. Missing code is construction
work, not a defect in an intentionally code-free recipe.

The design premise is to benefit from agents' growing competence, coding
ability and capacity to sustain larger abstractions. Preserve meaning while
letting implementations improve with those capabilities. Do not freeze the
framework around one generation's code or require an existing executable as
permission to begin. This direction sets no model-specific improvement schedule.

## The human leads from a shared map

The human pilots the tandem from a map of the intended whole: needs, purposes,
actors, universes, functional responsibilities, relationships, boundaries and
priorities. This can begin as a sketch, mind map or explained mental model; no
particular editor, diagram syntax or complete machine manifest is a prerequisite.
The agent helps make it explicit, identifies missing relationships and presents
consequences. The human directs intention and trade-offs; the agent contributes
reasoning, construction and maintenance within that direction.

Refine the map into ideal scenes, intentions and laws, then into ordered recipes
and concrete realizations. Return observations to the map and improve the recipes.
Do not start from the available code and shrink the intended whole to fit it.
Do not demand a perfect map before the first useful bounded construction either.
The conceptual map is not the technical fleet map or a runtime instance ledger.

## Prerequisite: a capable, well-educated agent

SHAPER builds on an agent capable of understanding instructions and abstraction,
following a human mandate, keeping context, distinguishing data from instructions,
recognizing uncertainty, using its available tools, and accepting correction.
It cultivates that competence with coherent context and ordered reading; it is
not a replacement for foundational model training or a promise to make any engine
competent by attaching a document.

Before construction, establish the agent's role, relevant context, continuity,
tools/access and ability to explain the map, scope and expected result. Resolve
ordinary implementation choices autonomously within the mandate; raise genuine
intentional ambiguities without inventing the human's goals. Update the recipe
when experience reveals a missing relation or constraint.

## Evaluate the right object

Evaluate recipes for clarity, coherence, sufficient detail, dependency order
and their ability to guide construction. Do not label an adopted recipe
"not implemented" or downgrade its ideal scene because no executable is supplied.
A genuinely undecided intention remains a decision to resolve.

Evaluate a concrete realization through its code, tests and actual behavior.
Keep those reports with that realization; an intention is neither an execution
claim nor a failed software release. Expected results may be specified before
construction without pretending that tests have already run.

## Elaboration and realization

Start from ideas, not an encoded implementation. Build shared understanding
progressively: a concrete situation, clarified words, relationships, then reusable
intentions and laws. A mental map supports the dialogue without imposing a tool.

**Elaborate:** make the intention understandable and transferable.
**Realize:** give it an appropriate form, put it to use and learn from its effects.
These activities recur at every scale; they are not separate mandatory products.

Human and agent challenge each other's interpretations constructively. Further
perspectives can reveal blind spots; agreement never guarantees objectivity.
Preserve useful meaning while revising choices explicitly. Constructive integrity
means fidelity to the intention, honesty about reality and useful correction.

DNA and morphogenetic fields may serve as illustrations, never as the framework's
mechanism or scientific foundation. The operative means are shared context,
explicit intentions, laws, human direction and revisable realizations.

## Specialized recipes and examples

The generic framework owns common intentions and laws. Specialized document
analysis methods, product composition and selected vector engines belong to the
owning brick or universe recipe outside this repository. SHAPER OS may illustrate
these through explicitly non-binding examples. An example is not a dependency
on a private catalogue or a mandatory composition for every universe.

This direction supersedes the treatment of the specialized document pipeline
as a universally required design contract in the reading map and Rule 22's
technology-specific general wording. It preserves provenance, access control,
private state ownership, declared lifecycle and verification of realized effects.
